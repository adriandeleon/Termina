# UX/UI feature and code review — 2026-10-20

Reviewed at commit `11141b9` (master, clean) on Debian 13 / GNOME on Wayland (XWayland), JDK 25.0.1,
JavaFX 27.0.1. Linux only; nothing here was run on macOS or Windows.

How: read the `com.termina.ui`, `config`, `shell`, `update` and `term` packages in full; two
independent passes over the renderer/input layer and the settings/lifecycle layer; and drove the real
app through `scripts/dev-run.sh -Dtermina.capture…` against a scratch `TERMINA_CONFIG_DIR` (twenty
runs: default window, three tabs, eight tabs at 520px, settings pages, palette, context menus,
profile dropdown, header-bar mode, hidden menu bar, light theme, selection, scrolling, full screen).

keybinding customisation, custom themes, OSC 8, block selection, copy-on-select, drag autoscroll,
selection dropped on keystroke, signing, Windows/Linux unrun, Wayland full-screen geometry, Quit

## 1. Verdict

The chrome is unusually well reasoned for a 0.7 — the focus guard, the chord-as-filter design, the
tab layout arithmetic and the capture harness are all the kind of thing that normally arrives at
2.0. The terminal itself is JediTerm's and behaves. The problems are at the seams: two things a
terminal user hits in the first hour (Escape leaving full screen, a selection that drifts under new
output), one data-loss button, one dead shortcut advertised in two menus, and a startup path that
closes the only window before the error dialog can be read. None is large; all are the sort that
make a first-time user conclude the app is flaky.

Fix first, in this order: §2.1, §2.2, §2.3, §2.4, §3.1, §4.1, §4.2, §4.3. Then §2.5, §3.2–3.5
and §4.4–4.7. Everything else is polish.

## 2. Bugs found by driving the app (verified)

### 2.1 Escape leaves full screen — and vim, less, fzf all use Escape
**High.** `TerminalWindow.toggleFullScreen` calls `stage.setFullScreen(true)` and never sets
`stage.setFullScreenExitKeyCombination(KeyCombination.NO_MATCH)` (nor `setFullScreenExitHint("")`).
JavaFX's default exit key is Escape, handled before the scene sees the key.

Verified: `-Dtermina.captureChord=F11,false,plain` alone reports `fullScreen=true`; the same plus
`-Dtermina.captureNativeChord=ESCAPE` (a real OS key press via `Robot`) reports `fullScreen=false`.
So in full screen, the first Escape in vim drops the user out of full screen instead of leaving
insert mode, and JavaFX also paints its "Press ESC to exit full screen" banner over the terminal.

Fix: both calls, once, where the stage is built. Pin it with a test on the chord table if full
screen ever gets a settings entry.

### 2.2 A selection does not follow its text when output arrives
**High.** `TerminalView.onHistoryLineCountChanged` is meant to shift `selection` and a scrolled-back
`scrollOrigin` as lines move into history. It is registered through
`buffer.addHistoryBufferListener`, but in JediTerm 3.76 that listener is fired only from
`clearHistory` and `moveScreenLinesToHistory` (resize), **not** from `scrollArea` →
`addLinesToHistory`, which is the path every ordinary newline takes (checked with `javap -c` on the
3.76 jar). So the method never runs for normal output.

Verified: `-Dtermina.captureCommand='seq 1 20; sleep 2.05; seq 1 100' -Dtermina.captureDrag=…`
copies `6 7 8` at drag time; 150 ms later the screenshot shows the same screen rows highlighted,
now over `75 76 77 78` (`shots/sel-pinned.png`). Copying then would give different text from what
is highlighted. The same gap means a user scrolled back reading a log is slid along as more arrives,
which is the first complaint every terminal gets.

The second reviewer reached the same conclusion independently with a headless probe against the
jar (12 newlines on a 4-row buffer: `history=9 listenerFires=0`; a shrink resize also fires
nothing), and adds that the count-delta trick stops working once scrollback is full, because the
count stops changing while lines keep moving.

Fix: drive the shift from the model listener (already called per mutation on the emulator thread)
and derive the delta from something that keeps counting when history is capped — JediTerm's
`TextBufferChangesListener.linesDiscardedFromHistory` plus the history count covers both. Add a
regression in `TerminalSessionPtyTest` style: select, write N lines, assert the selection's start
moved by −N; then fill the scrollback and repeat.

### 2.3 Close Tab and Close Window are the same chord on Linux and Windows
**Medium-high.** `MenuAction.appChord(W)` is `Ctrl+Shift+W` off macOS, and `shiftChord(W)` is
`Ctrl+Shift+W` everywhere. Both are registered; the filter runs bindings in order, so Close Tab wins
and Close Window's accelerator is dead while the File menu and the palette both advertise it
(`shots/palette.png` shows the two rows with identical chords). On macOS they differ (`Cmd+W` /
`Cmd+Shift+W`), which is why it was not noticed.

Fix: give Close Window a chord that is distinct per platform (`Ctrl+Shift+Q` is GNOME Terminal's,
Konsole uses `Ctrl+Shift+Q` too). Add a test that every registered accelerator in a window is
unique on both platform branches — `MenuActionTest` tests each chord, not the set.

### 2.4 An unstartable default profile closes the window before the error can be read
**Medium-high.** `TerminalWindow.openTab` on `IOException` does `tabs.getTabs().remove(tab)` and
*then* shows the alert. The removal fires the list listener: tabs empty and the stage showing →
`stage.close()` → `WindowManager`'s `onHidden` sees no windows → `Platform.exit()`. The alert then
opens on a closed owner, inside a toolkit that has been told to exit.

Verified with `profile.1.command=/nonexistent/x` + `profiles.default=bad`: the session log records
`could not start a shell … Exec_tty error:Unknown reason`, no window is left to open Settings from,
and the process sits in `showAndWait` until killed. The user's only way out is to hand-edit
`settings.properties`. A profile can get into this state by an uninstall, a typo in the command
field (no validation there, see §3.6) or a WSL distribution being unregistered.

Fix: on failure, keep the tab, show the error *in the tab* (a short message plus "Open Settings" and
"Retry with the default shell") rather than removing it; or at minimum show the dialog before the
removal and fall back to `settings.shell()` for the first tab. Also pass the command into the
message — "Exec_tty error:Unknown reason" is pty4j's text and says nothing.

### 2.5 The tab strip breaks at narrow widths: `+` sits on the last tab's close button
**Medium.** With eight tabs in a 520px window (`shots/hiddenmenu.png`) the tabs floor at
`TabLayout.MIN_TAB_WIDTH` (60) + 17 chrome, overflow the strip, and the floating new-tab/profile
buttons paint over the last tab's `×`. JavaFX's own overflow control is not shown, and there is no
scrolling. A 900px window reaches this at about eleven tabs. Fix: when `tabWidth` returns the floor,
either let JavaFX's tab-header overflow menu show (it is hidden only because the buttons cover that
corner) or move the two buttons into a managed slot to the right of the strip instead of floating.

### 2.6 Two system shells on Debian appear as profiles
**Low, but it is the first thing a Linux user sees in the chevron.** `ShellDiscovery` offers `Dash`
and `Sh` (`shots/profiles.png`), neither of which anyone opens a tab as — `sh` is a symlink to
`dash` here and dash is a scripting shell. Filter `sh`, `dash`, `rbash` from discovery (or
de-duplicate by resolved real path, which also collapses `/bin/bash` vs `/usr/bin/bash`). `tmux` is
in `/etc/shells` and is correctly excluded.

## 3. Code review — chrome, settings, lifecycle (from code unless noted)

### 3.1 Reset to Defaults deletes user profiles, geometry and everything else, with no confirmation
**High.** `Settings.resetToDefaults` is `properties.clear(); save();` and the button in
`SettingsWindow` (≈L171) calls it directly. The `profile.*` block is stored in the same file, so
four hand-made WSL/ssh profiles vanish on a click aimed at "put the font back". Needs a
confirmation that names what will be lost, and should probably not touch profiles at all (reset
appearance/terminal/window; offer profiles separately).

### 3.2 The settings file is rewritten in place; a crash mid-write empties it
**Medium-high.** `Settings.save` truncates and writes the live file. Power loss or a kill between
truncate and flush leaves an empty file; the next launch loads defaults and all profiles are gone,
silently. Write to a sibling temp file and `Files.move(…, ATOMIC_MOVE, REPLACE_EXISTING)`. An
`IOException` on save is logged at WARNING while the control still shows the new value — surface it
on the "Settings file" row.

### 3.3 Settings window goes stale while open; the first click on a stale control does nothing
**Medium.** `SettingsWindow.reload()` runs only on `show()`. The theme can change from the palette,
the menu bar from `Ctrl+Shift+M`, zoom from the chords, all while the window is open. Because
`Settings.put` ignores unchanged values, clicking the stale checkbox writes the value it already
has, so the first click is a no-op and the second does the opposite of its label. `setOnChange` is
single-consumer (taken by `WindowManager`); make it a listener list and have the settings window
subscribe.

### 3.4 Settings and About are owned by the first window that opened them, and die with it
**Medium.** Both guard `initOwner` with `getOwner() == null`, so "re-parented to whoever asked" in
`WindowManager.showSettings`'s comment is not what happens (and cannot: `initOwner` is illegal after
first show). JavaFX closes owned stages with their owner: open window A, open Settings, open window
B, close A — Settings disappears while B is live. Use an unowned stage, or recreate per owner.

### 3.5 A startup update check with no way to turn it off in the UI
**Medium (trust).** `updates.check` exists in `Settings` but has no row anywhere — not under
Advanced, not in About. A network request to GitHub on first launch, daily thereafter, controllable
only by hand-editing a file the UI never mentions is on, is the kind of thing that gets a terminal
emulator a Reddit thread. One checkbox under Advanced ▸ Updates, and say in About when the last
check ran.

### 3.6 A bad shell path is silently replaced; profile fields accept anything
**Medium.** `ShellLauncher.shellCommand` falls back to `$SHELL` when the configured path is not
executable, with no log line and nothing on the row. `settings.profileSource.system` sends users to
this field. Typing `/bin/zshh` and getting bash reads as "the setting is broken". Validate on edit
(executable? exists?) and show it inline; same for the profile command and directory fields.

### 3.7 Update bookkeeping triggers the full live re-apply to every tab
**Low-medium.** `setLastUpdateCheck` and `setDismissedUpdate` go through `put` → `onChange` →
every window → every tab rebuilds fonts and re-measures. This runs right after the first window
shows. `setWindowGeometry` already avoids exactly this; give bookkeeping keys the same quiet path.

### 3.8 Editable spinners throw on non-numeric text
**Low-medium.** Font size and scrollback spinners are editable with the default converter, so
`13px` + Enter raises an uncaught `RuntimeException` on the FX thread (lands in the debug log) and
the field keeps the bad text. Install a lenient converter or validate before commit.

### 3.9 Palette and menus: small frictions
- Nine "Go to Tab N" rows and "Go to Last Tab" are always listed in the palette, even with one tab;
  they drown the useful entries (`shots/palette.png`). List only the tabs that exist, by title.
- "Hide Menu Bar" reads "Hide" in the palette when the bar is already hidden.
- Zoom In's menu accelerator is `Ctrl++`, which no keyboard produces; the working key is `Ctrl+=`
  (handled by a special case in `onKeyPressed`). Register `EQUALS` as the accelerator so the menu
  tells the truth, keep `PLUS`/`ADD` as aliases.
- Settings search ranks by page order, not by match: "scrollback" lands on Appearance's "Show a
  scrollbar" while "Scrollback lines" sits on the Terminal page (`shots/settings-terminal.png`).
  Prefer title matches, or show one flat result list across pages.
- `settings.profiles.note` hard-codes "Ctrl/Cmd+Shift+1"; the window already has `shortcutName()`.
- `shellField.setPromptText("Leave empty to use $SHELL")` is the one untranslated string; the six
  bundles are otherwise key-identical (checked).

### 3.10 Accessibility of the settings window
**Medium.** Row titles are never `setLabelFor(control)`; every CheckBox is constructed without text,
so a screen reader announces "check box" with no name. Sidebar group headers ("GENERAL", "SYSTEM")
are only mouse-transparent, so Down from Appearance lands on a header row that selects nothing.
No Escape-to-close, no default button. All cheap.

### 3.11 Smaller code notes
- `Settings.readDouble` accepts `NaN`; `clamp` via `Math.max/min` passes it through to
  `Font.font(family, NaN)`. `WindowOpacity.clamp` already handles NaN — copy the pattern.
- `DebugLog` truncates `termina-session.log` at launch, so a second instance (a dev run without
  `TERMINA_CONFIG_DIR`) wipes the packaged app's log.
- `UpdateService` builds a new `HttpClient` per check and never closes it; `BodyHandlers.ofString`
  reads the whole body before the size cap, so the cap is the timeout.
- Manual update-check errors show raw class names (`UnknownHostException`); after
  `openReleasePage` the Help item stays "Version X is available…" and "Check for Updates" is
  unreachable until restart.
- `ShellLauncher` exports `LANG=en_US.UTF-8` when unset; on minimal images that locale is often
  not generated and bash prints `setlocale` warnings at every prompt. `C.UTF-8` is always there.
- `App` calls `Locale.setDefault` with the resolved UI language, dropping the country (`de_AT` → `de`)
  and switching away from the OS locale when the language is unbundled.
- `trackGeometry` saves size but not position; with two windows the last one closed wins.
- `WindowManager.open` cascades from the most recently opened window, not the one the action came
  from, and never clamps to the screen.
- The capture harness's stall meter reads ~1000 ms whenever a run opens extra tabs or the palette,
  and 54 ms for the same run with `-Dtermina.stallLog` on. One of the two meters is wrong; worth
  knowing which before trusting either.

## 4. Code review — renderer and input (from code; probe results noted)

The second pass checked JediTerm claims against the decompiled 3.76 jar and ran a small headless
probe against it for the first three items.

### 4.1 Pasted text is not sanitised, so bracketed paste can be escaped
**Medium, security-relevant.** `KeyEncoding.encodePaste` normalises newlines and wraps in
`ESC[200~ … ESC[201~`. Clipboard text containing a literal `ESC[201~` closes the bracket early
and the rest is typed input; other C0 controls pass through. xterm, iTerm2, kitty, WezTerm and
Windows Terminal all strip or neutralise these. Strip `ESC` and C0 (except TAB/CR) from pastes, and
see §5.2 item 4 for the multi-line confirmation.

### 4.2 No keyboard scrollback navigation
**Medium (UX).** Shift+PageUp/PageDown/Home/End are encoded to the shell as `ESC[5;2~` etc.; nothing
in `TerminalView.onKeyPressed` or the scene filter handles them. Every reference terminal binds
them. Four bindings in the view, before the encoder, when not on the alternate screen.

### 4.3 Wheel scrolling ignores magnitude
**Medium (UX).** `onScroll` does `signum(deltaY) * 3` lines per event and ignores `isInertia()`.
Trackpads and high-resolution wheels deliver many small events, so scrollback flies by; the mouse
*reporting* path already converts pixels to lines properly. Accumulate `deltaY / lineHeight` as
`MouseEncoding.unitsToScroll` does.

### 4.4 A program's cursor shape is permanent for the tab
**Medium.** `FxTerminalDisplay.setCursorShape(null)` is ignored, but null is what `JediTerminal.reset()`
sends to clear the shape, and `JediEmulator` maps DECSCUSR 0 ("reset to default") to `BLINK_BLOCK`.
vim restoring the cursor on exit forces a block in a tab where the user chose bar or underline. The
null case is a one-line fix here; the 0 case needs a `JediEmulator` subclass. Also no blink at all
and no hollow unfocused cursor, with no setting for either.

### 4.5 Drag selection highlights one cell more than it copies
**Medium.** `TerminalSelection.intersect` treats `end.x` as inclusive; `SelectionUtil.getSelectionText`
uses an exclusive `substring`. Probe: drag (0,0)→(4,0) over `hello` highlights five cells and
copies `hell`. `wordSelection` compensates with `+1`, which makes double-click highlight one extra
cell instead. Pick one convention and adjust at drag time.

### 4.6 Stale anchor produces phantom selections inside mouse-reporting programs
**Medium.** When a press is reported to the program, `selectionAnchor` keeps an earlier plain
click's point; in mode 1000 (press/release only — `less --mouse`, many TUIs) `encodeDragged`
returns null and the drag falls through to local selection anchored there. Null the anchor when a
press was reported.

### 4.7 Rendering performance against the project's own convention
- **Any non-ASCII character drops the whole run to per-glyph `fillText`** (`isPlainAscii` rejects
  everything above 0x7E). Box-drawing, block and braille characters — every TUI border and bar —
  take the slow path, so a 200×50 htop frame is ~10k draw calls instead of a few hundred. Only
  astral and DWC cells need it.
- **Every layout pulse during a window drag reflows the entire scrollback** under the buffer lock
  (`postResize` → `TerminalTextBuffer.resize`) and ioctls the PTY. Debounce the terminal resize
  (50–100 ms) while resizing the canvas immediately.
- **The visual bell is not coalesced**: each BEL queues a `runLater` and a new `PauseTransition`;
  `cat` of a binary file queues thousands. One pending flag.

### 4.8 Smaller renderer and input notes
- The cursor disappears when a line is exactly full: JediTerm's deferred wrap leaves
  `cursorX == width` and the draw bails on `column >= columns`. xterm draws it on the last column.
- The link underline only appears if the mouse moves while the modifier is held — only
  `KEY_RELEASED` calls `onLinkModifierChanged`, which defeats the stated discoverability goal.
- Ctrl+Alt+letter and Ctrl+3/4/5/7/8 send nothing (the control branch requires no Alt, the meta
  branch no Ctrl, and KEY_TYPED drops controls). Readline's `C-M-f` has no route.
- Numpad arrows with NumLock off (`KP_UP` etc.) are not in the key table and go unconsumed.
- `MouseEvent.Type.MOVED` is never reported, so mode-1003 programs get no motion.
- A selection survives an alternate-screen switch (`scrollOrigin` is reset, `selection` is not),
  so a prompt selection is drawn over vim and Copy yields alt-screen text.
- The block-cursor glyph redraw indexes by column rather than slot, uses the regular font and
  ignores the cell background.
- `lineHeight = ceil(fontSize × 1.18)` ignores metrics; JetBrains Mono needs ~1.32 em, so
  descenders are overpainted by a coloured row below.
- `TerminalSession.close()` waits up to 500 ms per tab on the FX thread for executors to stop.
- `CommandMatcher`'s memo never caches failures (`MIN_VALUE` is both "unvisited" and "no match").
- `OpenCommand`'s Windows fallback is `cmd /c start "" <file>`, so `&`, `|`, `^`, `%VAR%` in a file
  name are interpreted by cmd on Ctrl+click.

## 5. UX and feature review

### 5.1 What is good, and should not be changed
- The chord policy (`Ctrl+Shift` off macOS, `Cmd` on) and the filter-not-accelerator design are
  right, and the palette lists the real chords because they are the same objects.
- The focus guard. Most JavaFX apps never get this right.
- Live-apply settings with per-row explanations, and rows that disable themselves with the reason
  (`showMenuBar.mac`, `menuBarInTitleBar.unsupported`) instead of silently doing nothing.
- The tab strip: fills the width like macOS Terminal, reorders by drag and by keyboard, hides when
  single, shows the directory on hover, confirms only when something is running and names it.
- The header-bar mode is clean (`shots/headerbar.png`) and correctly limited to windows opened after.
- The right-click menu: link items only when over a link, zoom row, settings always reachable.
- The capture harness and the extracted-decision tests. Keep adding to both.

### 5.2 Gaps a Linux/Windows user will notice in the first week
1. **No middle-click paste, no Shift+Insert paste, no Shift+PageUp scrolling** (see §4.2). Only the primary button is handled in
   `TerminalView`; `Shift+Insert` is encoded to the shell as `CSI 2;2~`. Both are reflexes on
   Linux (and Shift+Insert on Windows). Middle-click should paste the X primary selection where
   there is one; `Shift+Insert` should paste the clipboard. Both are small.
2. **Tabs with the same directory are indistinguishable** (`shots/main.png`: three tabs, all "~").
   `TerminalTitle.tab` falls back to the directory name; it should fall back to the foreground
   program first (`RunningProgram.first(pid)` already exists and `CwdWatcher` already polls) — "vim",
   "ssh", "npm" — and only then the directory. Optionally a small index badge so `Alt+N` has
   something to point at.
3. **No "reopen closed tab", no "rename tab", no "duplicate tab".** Rename is the one people ask for
   first in a tabbed terminal; it also solves 2 for anyone who cares.
4. **Paste safety.** Multi-line paste goes straight in (bracketed paste only if the shell asked).
   A one-line confirmation for a paste containing a newline, off by default or on by default, is
   now standard (Windows Terminal, iTerm2, kitty). Pair it with the sanitising in §4.1.
5. **Scrollback search** is already on the list; it is the single most-asked feature and the
   palette is the natural home for its entry.
6. **A keyboard-shortcut reference** (a palette entry or Help item that lists the chord table).
   There is no place in the app that shows all of them at once.
7. **Bell**: visual only, no option to be audible or to mark the tab when a background tab rings.
   Tab activity/bell indicators are the other half of having tabs.
8. **Light theme** (`shots/light.png`): the ported palettes are faithful, as intended, but ANSI
   black-on-default-fg prompts (powerline segments) come out black-on-black. Not Termina's bug;
   worth a note in the theme description, since the first thing a user tries after switching is
   their prompt.

### 5.3 Against the author's own landscape notes
`docs/competitive-landscape.md` picks four durable gaps: splits, a text config a GUI writes,
ligatures + an image protocol, one artefact per platform. The second and fourth are done. Splits
are the one that would change which category Termina is in, and the current `TerminalWindow` (one
`TabPane` of `TerminalView`s, settings applied per view) is shaped to take them — a `SplitPane`
inside a tab is a contained change, the hard parts (focus guard, chords, title binding) already
assume "the active terminal" as an indirection. Ligatures depend on JediTerm's cell model and the
per-glyph fallback already in the renderer; defer. The kitty keyboard protocol is called out as
cheap and is not started; it would be the first thing a Helix/Neovim user checks.

Before any of that, the eight items at the top of §1. They are all under a day each and they are
what a reviewer of 0.8 would hit first.

## Appendix — reproduction commands

All runs used `TERMINA_CONFIG_DIR=<scratch>` so nothing touched `~/.termina`. Screenshots are in
the session scratchpad (`shots/*.png`); they are not committed.

```bash
# §2.1 full screen: with and without the OS Escape
scripts/dev-run.sh -Dtermina.capture=/tmp/fs.png -Dtermina.captureChord=F11,false,plain
scripts/dev-run.sh -Dtermina.capture=/tmp/fs.png -Dtermina.captureChord=F11,false,plain -Dtermina.captureNativeChord=ESCAPE
# §2.2 selection pinning
scripts/dev-run.sh -Dtermina.capture=/tmp/sel.png -Dtermina.captureCommand='seq 1 20; sleep 2.05; seq 1 100' \
  -Dtermina.captureAfterCommandMs=2000 -Dtermina.captureDrag=40,120,400,180
# §2.4 unstartable default profile (settings.properties):
#   profile.1.id=bad  profile.1.name=Bad  profile.1.command=/nonexistent/x  profiles.default=bad
# §2.5 narrow strip
scripts/dev-run.sh -Dtermina.capture=/tmp/tabs.png -Dtermina.captureTabs=7 -Dtermina.captureResizeTo=520,320
```
